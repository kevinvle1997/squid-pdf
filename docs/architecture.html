squid-pdf: how the in-place PDF text editor works

A web app that opens a PDF, lets you retype any line in the file's own font, previews the change as server-drawn image strips, and downloads a real edited PDF. This guide walks the code from the proxy down to MuPDF's content streams, then back up to what the person in front of the screen sees.

Python 3.14 · FastAPI · pebble · PyMuPDF 1.28 · fontTools React 19 · react-aria · Vite ~12.1k lines of Python in src ~5k lines of TypeScript 50 commits · AGPL-3.0

01What it is

squid-pdf changes the words in a PDF without turning the page into an image or covering text with a white box. When you replace a line, the server removes the old glyphs from the page's content stream, then writes new ones. Wherever it can, it uses the font embedded in the file. If it can't, it uses a bundled face with the same widths.

Edit in place

Text is grouped into spans (one style, one baseline). A span id is a hash of its page, position, font, text and order. The span index is built once, at upload, so ids never move.

Honest about fidelity

Every span is judged exact, approximate (with a reason) or substitute before you touch it. The UI tells you when an edit will not match.

Redaction removes text

A redaction deletes the text and every hidden copy of it, such as metadata, bookmarks, form values and screen-reader text. The saved file is then reopened to prove the words are gone. If they aren't, nothing downloads.

Disposable by design

There are no accounts. A random __Host-owner cookie owns the documents a browser uploads. A document is deleted one hour after its last request.

The code is split into four Python packages with one-way dependencies (api → editing → documents → core) and a React client with the same discipline. Tests enforce the import rules, the dataclass rules and the "every constant is read" rule.

02Runtime topology

Two containers in production. Caddy serves the built React app and proxies /api/* to one Uvicorn process. That process does no PDF work itself: every parse, render and save runs in a pool of spawned worker processes, which can be killed when they run too long or use too much memory.

03Layers and the rules that hold them

The layering is enforced by tests, not left to convention. tests/test_layers.py parses every module with ast, imports inside functions included. react/src/layers.test.ts does the same for the client.

Other rules the tests enforce

  • State shape: classes may not use self._x attributes. Every non-exception class is a dataclass. Only "holders" (@dataclass(slots=True), not frozen) may change after construction; everything else is frozen.
  • Tables: a module-level dict or tuple of rows outside a constants.py must be _private. Four exceptions: QUARTER_TURNS, CATALOG, FACES, MUPDF_FAILURES.
  • No dead constants: every UPPER name in a constants.py must be read somewhere. Only MAX_FONT_BYTES and MAX_FONTS are exempt; they wait for font attach (#52).
  • Pool jobs pickle: every task sent to a worker is a module-level function bound with functools.partial. Lambdas are not allowed.
  • CSP stays in sync: policy.test.ts hashes the inline style React Aria injects and checks that the Caddyfile's CSP allows exactly that hash.

04A request's path through the server

The same chain serves every API call. Controllers are frozen dataclasses built per request with the pool injected. They return a framework-free Reply(body, headers, status), which routing.response_of turns into raw bytes.

Dependency order on upload

The upload route runs _admit_pdf_only → rate.admit_upload → owner.token, and none of them reads the body. The Content-Type check runs before the rate count on purpose: a cross-site form can't send application/pdf, so it can't use up a user's quota.

Caching contract

  • Document JSON: private, no-cache with an ETag of xxh3_64(analysis digest + reply digest(lang)). A 304 reads only the digest file. expires_at is left out of the ETag on purpose.
  • Page PNGs and font list: immutable only when the request's build equals the server's BUILD (mupdf-<ver>.fonts-<lib>.google-<sha7>). Otherwise no-store. A deploy that changes MuPDF, the bundled fonts or the Google pin therefore busts every cache.

06The worker pool

api/pool.py wraps a pebble ProcessPool, chosen because pebble can kill a hung worker. Backpressure is an asyncio semaphore, not pebble's queue, so a waiter who gives up costs nothing.

07Flow: opening a PDF

The upload is streamed to disk, checked as it arrives, then analysed once in a worker. The analysis builds the span index, judges each span's fidelity, measures each font's glyph widths for the browser, and is saved for later reads.

What the Document reply carries

pages[]

{width, height, turn_cw}. Page images are always drawn unrotated, and the browser turns them.

spans[]

id, page, text, font, size, color, bbox, origin, fidelity, why, form_field. Spliced in from disk as an orjson.Fragment, never re-parsed.

fonts[]

name, substitute, why, same_widths, glyphs. Per-letter widths in thousandths of the size, so the browser runs the same fit check while you type.

fit · copy · notices

The server's thresholds (4 pt, 5%, 0.9) and every sentence template the browser needs, in the reader's language. no_text is a notice when the PDF has no text layer.

08Flow: editing and the live preview

Typing never touches the network. The browser checks fit with the server's own widths, shows a preview in the same TTF the server will draw with, and asks the server for real pixels only when you commit. The server then redraws only the horizontal strips that changed.

How regions are chosen

strips.ts takes each changed span's bbox plus 2 pt, merges rows that touch, and sends one full-width region per merged row. The server refuses strips that overlap, regions off the page, more than 10,000 regions, and pixel rows over twice the page height. On the server, plan(strips=…) redraws only the spans whose box, padded by 0.5 em for accents and tails, reaches a strip. Turned text is redrawn wherever the page is drawn.

09Flow: export

Export replays the same edit list on a fresh copy of the original, saves it to scratch space the server made, verifies any redactions by reopening the saved file, and streams the bytes back.

10The edit engine

editing/apply.py turns the wire edits (Replace, Redact, Insert) into engine primitives. The engine itself never knows what a "Replace" is. It only knows erase, unlink, drop hidden copies, draw and save.

How erasing works in MuPDF

  1. Read the page's letters (rawdict). For each span box, build a thin strip through each letter, between 5% and 20% of its height above the baseline, padded by 0.1 pt. A strip is needed because MuPDF removes every glyph whose box touches the area, and glyph boxes reach into neighbouring lines.
  2. Take the file's own pre-existing /Redact annotations out of /Annots, temporarily set /Rotate to 0, create one redact annotation per box, and apply pdf_redact_page with text removal only: no black boxes, images untouched, line art untouched.
  3. Put the file's own marks and links back as the same objects. Re-read the boxes; any box still holding text is redacted again as a whole, so old text never shows under new.
  4. Restore any font resource the redaction stripped that this edit still names.

How drawing works

  • Face we ship: added to the page once under a content-hashed resource name (S + 12 hex characters), then written with Shape.insert_text.
  • File's own font, by letter: each letter maps to the copy that draws it (the file's own copy, another copy of the same font, or Google's). Runs split wherever the copy changes. Lent fonts are subset on save.
  • File's own font, by code: for symbol-cmap TrueType or Type0 Identity-H fonts reached only through ToUnicode. q … BT … Tm /Res size Tf <hex> Tj ET Q is written by hand.
  • New streams go last in /Contents. The page's own stream is wrapped once in q…Q so its graphics state can't leak. An ExtGState keeps the original opacity.

11Fitting new text

The product rule is to offer a choice and never silently squeeze. delta_pt is the typed width minus the original width, measured with the same DrawPlan that will draw it. The thresholds are in core/constants.py and are sent to the browser, so client and server agree.

A FitReport also explains missing letters, in this order:

  • chosen_unavailable: an insert's font can't be used.
  • missing: "no é in this font, so the line is drawn in Liberation Serif Bold".
  • will_leave_out: no font we have can draw the letter, e.g. 中.
  • too_long.
  • not_offered.

12Fonts and fidelity

Most of the engineering is here. The aim is to redraw in the file's own font whenever possible. When the file's copy is a subset missing the letter you typed, the engine borrows it from another copy of the same font, or from Google Fonts, and checks that the borrowed copy really is the same font before mixing it in.

Google Fonts copies

google-families.json lists 2,030 families at a pinned commit, with each file's git blob SHA-1. Matching a font to a file needs no network. Only an analysis may download, waiting at most 5 s, and the download must match the pinned hash. Variable fonts are cut to the exact weight with instantiateVariableFont, deterministically. A failed fetch is held back for 10 minutes. If nothing answered at all, every file is held back; a 404 holds back only its own file. Families with a Reserved Font Name are never cut. Setting SQUIDPDF_NO_FETCH=1 turns fetching off (the test suite does).

13Redaction: a verified removal, not a black box

The redaction engine exists in the API and CLI, but the browser UI doesn't create redactions yet (render.ts:43: "nothing inserts or redacts yet"). It is still the most heavily tested path in the codebase.

Where hidden copies are found

  • Marked content ActualText/Alt/E in page streams, Form XObjects, tiling patterns, soft masks, Type3 glyph procedures and annotation appearances
  • Info title/author, XMP metadata (non-XML metadata is dropped whole)
  • Bookmarks, comments (/Contents, /RC, FreeText)
  • Form values /V /DV /RV /Opt /TU, XFA datasets
  • Structure-tree Alt text
  • Signatures: /V dicts, /Perms, /DSS

Checked twice, by the same code

At render: an in-memory verdict per span. A failure adds the notice "This text couldn't be removed, so the file can't be downloaded with this redaction."

At export: the saved file is reopened. Any word left, on the page or in a hidden copy, raises redaction_failed, deletes the file, and sends nothing.

Both paths share _words_left, so the warning and the refusal can't drift apart.

Side effects the user is told about

"These words were also in this file's title, bookmarks… The file you download leaves them out."

"This file is signed, and a redaction changes it, so the file you download has no signatures."

Links over redacted text are removed (a mailto: can carry it). A plain replace keeps links and signatures.

Words are matched NFKC-normalised, case-insensitively, as whole words, longest first, and also as the whole text joined by [\W_]*. The content-stream lexer is MuPDF's own pdf_lex, cross-checked against a <</>> depth count. If they disagree, or an inline image can't be read past, every string after that point is treated as a possible hidden copy.

14Storage and document lifetime

There is no database. Each document is a folder named by a 22-character random id, and the folder's mtime is its idle clock.

$SQUIDPDF_DATA/                       # /data in the image, ./data in development

├── .trash-<id>/                      # a delete in progress: renamed first, so the id stops resolving at once

15The browser editor

There is no router and no state library. App.tsx holds one useState<Opened | null>. The editor is a hand-written external store read through useSyncExternalStoreWithSelector, so each component redraws only when its slice changes.

Client-side checks that mirror the server

  • Text sanitising (typing.ts:31-34 ↔ edits.py check_text): tab and line break become a space; other controls, separators, lone surrogates and bidi embedding or override characters are dropped. ZWJ, ZWNJ and U+202F are allowed.
  • Fit (fit.ts ↔ editing/fit.py): the same tolerance, shrink floor and condense limit. A whitespace character with no glyph counts as 0.25 em. Once the render lands, the server's verdict replaces the client's.
  • Screen reader: trouble is announced only when its kind changes, not on every key.

16User flows, step by step

A · Open

Drop or pick a PDF

  1. Drag onto the window (the whole window is a react-aria DropZone) or press Choose a PDF.
  2. XHR upload with progress: "Sending contract.pdf 64%", then "Reading the text of contract.pdf".
  3. On 201 the editor mounts. On failure the server's detail shows in red, and you can try another file.
B · Look

Inspect a line before editing

  1. Pages load lazily as they come near the viewport (100% margin).
  2. Hover for 250 ms, focus, or tap a span to see its note: substitute font, form field, or the fit message after an edit.
  3. Spans in a substitute font are marked from the start.
C · Edit

Retype a line

  1. Double-click (selects the word) or press Enter/Space on a focused span (selects all).
  2. Type. The field is drawn in the preview face at the span's size and colour. A chip shows "Liberation Serif 11 pt" or the trouble.
  3. Enter keeps, Esc discards, and Tab or a click elsewhere keeps. A blank line is never kept.
  4. The preview appears, then the server strip replaces it. The margin gets an Undo: "new" goes back to "old" button.
D · Undo

Change your mind

  1. ⌘Z undoes and ⌘⇧Z or ⌘Y redoes, when focus is outside a text field (inside one, the field's own undo works).
  2. A margin button puts back every edit to that span and clears redo.
  3. Editing back to the original text counts as no change.
E · Export

Download the result

  1. ⌘S (works while typing; the draft is committed first) or the Export button.
  2. The file downloads under its original name.
  3. A notice reads "Downloaded sample.pdf.", or the export warning, or the error.
F · Recover

When things go wrong

  1. Offline: render fails with "Couldn't reach the server…" and the preview stays; the online event retries.
  2. An hour idle: the next call gets 404, the editor re-uploads, and you see "This document's hour ran out, so it was opened again from this browser."
  3. A crash shows "Something went wrong, and this page stopped".

How exceptions become Problems

API_ERRORS = CORE_ERRORS.with_rows(WORKER_FAILURES, FRAMEWORK_FAILURES). The first isinstance match wins, and a test checks that no row sits below a broader one.

  • MuPDF rows: FzErrorLimit → too_heavy. FzErrorSystem → a regex on the message (malloc|out of memory|…) picks too_heavy, otherwise 500. FzErrorBase → damaged.
  • Worker rows, as in the pool diagram.
  • Framework rows: RequestValidationError → 400. Starlette 404 → not_found, 405 → method_not_allowed, others → 400.

A Problem raised inside a worker survives pickling via __reduce__, with its fill values intact.

types a lot more text than fitsThe chip and the screen reader say "N pt too long". It is drawn as-is and runs past the original end. There is no shrink or condense choice in the UI yet.
types a letter the embedded subset lacksBorrowed from another copy or Google if the fonts match. Otherwise the whole line moves to the substitute, and the bar counts it as "in a similar font".
types a letter no font has (CJK, emoji)Reported as left out; the line keeps its own font when switching wouldn't help.
pastes text with newlines or tabsThey become spaces. Bidi controls and lone surrogates are dropped in the browser and rejected by the server.
clears a span completelyNot recorded ("emptying a span isn't a replacement"). Removal is what redaction is for.
retypes the original wordsThe edit isn't sent; the strip disappears and the count goes back.
edits text inside a form fieldWarned before editing. On render the edit is left out with a notice; the page text in the same spot is still editable.
edits a rotated or right-to-left lineAllowed, but marked approximate: the new text is drawn level, left to right.
types fast, committing many editsEach commit aborts the in-flight render. Only the newest reading is drawn, and only stale pages are requested.
presses ⌘Z while in the fieldThe field's native undo, not the document history.
presses ⌘S mid-wordThe draft is committed and exported. The browser's "save page" is prevented.
loses the networkRender shows "Couldn't reach the server…" and the browser preview stays. Coming back online retries automatically.
leaves the tab for over an hourThe document is swept. The next image or request 404s, the browser re-uploads its in-memory copy, and the edits still apply because span ids are stable.
reloads or closes the tabEverything is lost back to the last export. There is no warning prompt. The server copy expires an hour later.
shares the document URL or idAnother browser gets a 404 identical to an unknown id.
keeps working across a deployPage and font caches are keyed by build. A changed analysis is redone on read. A lazy chunk that can't load shows the crash screen.
opens a huge or pathological fileOver 100 MiB → 413. Over 1,000 pages → 422. Over 1 GiB in a worker → too_heavy. Too slow → too_slow. Large pages get a smaller image scale (20 MP cap).

Performance budgets asserted in tests:

  • Save time grows linearly with pages: 300 pages take at most 5× the time of 100.
  • A 1,000-page dense document exports within 60 s through the API.
  • A tall page cut into thousands of strips renders within 10 s.
  • The index is read once per worker.
  • A font shared by every page is opened once.
  • With GitHub not answering, an upload waits once and a render never waits.

22Deploy and CI

compose.yaml

  • app: Python 3.14-slim, uid 999, --extra api, read-only root, tmpfs /tmp sized SQUIDPDF_APP_SCRATCH (N × 256m), mem_limit SQUIDPDF_APP_MEMORY (worst case N × 1792m + 1024m). init: true reaps pool children. No published ports.
  • proxy: Caddy with the built SPA, fixed IP 172.31.255.2 (the other containers draw from .128/25, so none can take it), ports 80/443/443-udp, 512m.

Caddyfile

  • basic_auth on every path, including health. Remove it and the site is public.
  • CSP default-src 'none', plus self for scripts, images, fonts and connect, and one React Aria style hash; frame-ancestors 'none'.
  • HSTS, nosniff, Referrer-Policy same-origin, a strict Permissions-Policy.
  • Uvicorn keep-alive is 130 s, longer than Caddy's idle time, so Caddy never reuses a closed connection.

CI jobs (.github/workflows/ci.yml)

  • backend: ruff, ruff format, mypy, ty, pytest -n auto
  • image: builds the test target and runs the CLI tests inside it
  • frontend: biome, types:check (OpenAPI drift), tsc, vitest (node + Chromium), Playwright e2e against real uvicorn
  • deploy: compose up --wait with a throwaway password, then deploy/check.sh
  • report: green rate on the sample, without the api extra

23Gaps worth knowing

The server is ahead of the UI in several places. These are the differences a new contributor is most likely to trip over.

  • The UI only replaces text. Redact, insert and fit strategies all work through the API and CLI, and their sentences (undo_redaction, option labels) are already shipped to the browser. No control creates them yet, and there is no font, size or style picker (/api/fonts exists for one).
  • Reload loses work. Edits live only in memory. A beforeunload prompt or local persistence of the edit list plus the File would close this. The server side already copes with a re-upload.
  • No way back to the drop screen besides reloading, and the client never calls DELETE; documents always live out their hour.
  • IPv6 rate limiting is shared in the compose deployment, because the Docker network is IPv4-only and every IPv6 client appears as the gateway.
  • Support address is a placeholder: support@example.com in too_slow and too_heavy.
  • Only English exists (en.toml). Negotiation, per-language ETags and the browser-side {placeholder} filling are already built for more.
  • Licence coupling: PyMuPDF is AGPL. The PdfDriver protocol was drawn so a pypdfium2 + pikepdf driver could replace it by changing one import.
  • Reserved limits: MAX_FONT_BYTES (25 MiB) and MAX_FONTS (20) wait for "attach your own font" (#52), which would sit before Google in the lender chain.
